# GC Wrapped

Group chat analytics platform: chat exports → Postgres warehouse (dbt) → LLM enrichment → RAG Q&A with citations → "Wrapped" profile per member. Resume project for Ryan Phan (new-grad SWE / data eng). Planning happens in a separate claude.ai project; this file is what you need to work in the repo.

## Every session
Context is cleared after every session. Anything not written into the repo is lost, so write it down.
1. Read `docs/STATUS.md` (where things stand) and skim `docs/decisions.md` (why things are the way they are).
2. Ryan pastes a session brief. Do that task only. If it conflicts with STATUS/decisions, or expands scope beyond the current phase, say so before writing code.
3. When Ryan says "wrap up" or the task is done: run `make lint test`, update `docs/STATUS.md`, append any new decisions to `docs/decisions.md`, and propose a commit message.

`docs/STATUS.md` is the handoff back to the planning chat: Ryan pastes it there to plan the next session. Write it for a reader who wasn't in this session. Be specific about what's broken, what you deviated from in the brief and why, and anything you need decided.

## Privacy rules (hard requirements)
- You are a third-party API. Real chat data must never enter your context.
- Never read, print, grep, list contents of, or open anything under `data/`. Never read, list, or search anything outside this repo; real chat exports live elsewhere and you must never access them.
- All test data is synthetic: use only fixtures in `tests/fixtures/`, generated by `tests/synthetic/instagram.py` (`make synth`). Never ask for or accept pasted real messages.
- Never read or reference `~/gcw-private`, any `real.env`, or the `gc-wrapped-real` compose project. Never run make with an ENV_FILE other than the default `.env`.
- Only connect to the `gcw_dev` database (synthetic data). Never run psql, dbt, or scripts against `gcw_real`, and never run any make target containing "real".
- Ryan runs real-data commands in his own terminal and reports aggregate numbers. Never ask him to paste real messages, names, or output containing them.
- Logs and error messages never include message bodies, sender names, phone numbers, or emails. Log counts, IDs, durations, file hashes.
- Never commit chat data, media, `.env*`, or `members.yaml`. `data/` stays in `.gitignore`.
- Ingestion is deny-by-default: it loads only threads whose numeric ID is in `GCW_THREAD_ALLOWLIST` and fails if that is unset or empty. Never add a bypass (no "synthetic mode" switch, no flag, no default that skips it); dev `.env`, `.env.example` and CI list the synthetic thread IDs explicitly.
- No external API calls from pipeline code in Phase 1.
- The Instagram format spec is `docs/formats/instagram-schema.md`. Build against it, not against assumptions.

## Stack

## Conventions
- Business logic lives in `src/gcwrapped/`; DAGs only call it. Everything runs and tests without Airflow.
- Type everything; `mypy --strict` passes. Config comes from env via `config.py`, never hardcoded.
- Every new behavior gets a test. Parser fixtures cover edge cases deliberately.
- Ingestion is idempotent: re-loading the same file inserts 0 rows (dedup key design is in decisions.md).
- Small diffs. Prefer boring, widely used libraries; justify any new dependency in decisions.md.
