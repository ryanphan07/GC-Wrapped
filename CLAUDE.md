## Privacy rules (hard requirements)
- You are a third-party API. Real chat data must never enter your context.
- Never read, print, grep, list contents of, or open anything under `data/`. Never read, list, or search anything outside this repo; real chat exports live elsewhere and you must never access them.
- All test data is synthetic: use only fixtures in `tests/fixtures/`, generated by `tests/synthetic/instagram.py` (`make synth`). Never ask for or accept pasted real messages.
- Never read or reference `~/gcw-private`, any `real.env`, or the `gc-wrapped-real` compose project. Never run make real-ingest or any command with a non-.env ENV_FILE; real-ingest is verified only by the real-ingest-synthetic CI job. Tests that exercise the refusal path through subprocess are fine. Host-side settings load only the file named by ENV_FILE.
- Only connect to the `gcw_dev` database (synthetic data). Never run psql, dbt, or scripts against `gcw_real`.
- Never inspect or contact real containers: no docker inspect, logs, exec, cp, top or stats on them, no compose command with a real env file, no connection to 5433, 8083 or 8084. Reading container names and compose-project labels from `docker ps` is allowed. `gc-wrapped-real-db-1` may be running while you work; that is expected.
- Ryan runs real-data commands in his own terminal and reports aggregate numbers. Never ask him to paste real messages, names, or output containing them.
- Unhandled CLI errors print `gcw: failed: <ExceptionTypeName>` only. `GCW_TRACEBACK=1` re-raises for the full traceback: dev only; never set on real-data runs.
- Logs and error messages never include message bodies, sender names, phone numbers, or emails. Log counts, IDs, durations, file hashes.
- Never commit chat data, media, `.env*`, or `members.yaml`. `data/` stays in `.gitignore`.
- Ingestion is deny-by-default: it loads only threads whose numeric ID is in `GCW_THREAD_ALLOWLIST` and fails if that is unset or empty. Never add a bypass (no "synthetic mode" switch, no flag, no default that skips it); dev `.env`, `.env.example` and CI list the synthetic thread IDs explicitly.
- No external API calls from pipeline code. Hosted providers fail closed unless the D76 NER gate (P2-2b) has passed (D84); a local model needs no API call.
- Every piece of work needs the sender's explicit opt-in in the consent ledger, at two levels (D88): `yes` (local work and redacted external calls) or `local` (this machine only). Local work (labeling, tagging, embeddings, answers, profiles) uses `local_ok` AND `has_user_text` (D95: non-blank and not an Instagram placeholder); no message text leaves the machine except through `gcwrapped.redaction` (D70, D77), and only for messages `external_ok` (consent yes, D69). Blank, `no` and missing senders are excluded from everything: no relation `gcw_reader` can read counts or names them, Activity marts included (D128; sessions and reply times are still shaped by their timestamps, D125), and a new reader grant needs its check in `dbt/tests/reader_relations_are_consented.sql`. The Ask page connects as `gcw_ask`, read-only and granted only what answering reads (D127, `gcwrapped.dashboard.ask_role`): the consent-filtered views `analytics.ask_messages` and `analytics.ask_message_embeddings` and the default tables (D131). Answering reads message text and vectors only through those views; never grant `gcw_ask` a relation that holds every sender. Claude Code never reads, creates or edits the real ledger.
- The Instagram format spec is `docs/formats/instagram-schema.md`. Build against it, not against assumptions.

## Commands
Model commands (tag, tag-eval, embed, retrieval-eval, answer-eval, ask, grade-answers, dashboard-up, eval-all) refuse while another GC Wrapped project's llm or embed containers run (`failed at docker (OtherStackRunning)`), and every one of them, `tag --no-start` and each Ask page question read `/v1/models` first and fail closed unless the expected model is served (`failed at model (ServedModelMismatch)`) (D126).
Every retrieval-eval and answer-eval pass, alone or in eval-all, prints available memory and swap in use at its start and end, is refused if more than 256 MiB of swap is in use (`failed at memory (SwapInUse)`) and fails, storing nothing, if swap grew by more than 256 MiB (`(SwapGrew)`); answer-eval also restarts the llm service first. The limits are fixed (D126). answer-eval and ask print invalid outputs per fixed reason.
